## Why numbers changed (applies to every row marked changed)

1. Flight fixes between the two batches: G-06 (interior seed 7 atrium-tree contact), G-07 (UAV-UAV separation floor of 2.5 m), G-08 (every UAV completes laps; window-independent primary metric), plus the waypoint-copy fix to the offset_ring routes and the exterior patrol layer raised from 20 m to 22 m (Bravo 24 m to 26 m; 626b71f) so Alpha clears the 19.2 m roof beside leg patrol_cp6 -> cp7. The flown paths therefore differ run by run.
2. UAV window is 300 s in the rerun (was 500 s in Part 1). Anything summed or counted over the run (thrust effort, laps, detections that need time) scales with it. The guard windows are unchanged.
3. Equal-window revisit (G-08): the Part 1 video used worst revisit over each run's own window, which is not comparable between a 300 s UAV run and the guard's own longer run. The rerun adds a metric over one common window.
4. G-14: the interior detection path was reworked; the rerun measures it, it does not assume an improvement (see section 2).
5. Economics (E077): kappa, NCRI, payback and the FMEA are recomputed from the new CSV and the ablation CSV, so they move with the cycle times and revisits above. All cost inputs are still ASSUMPTION ranges; ratios only.
6. The guard condition uses the same seeds and the same guard model in both batches, so guard rows are expected to be identical.

Obstacle contacts in the rerun: none in any UAV cell (section 3, parsed from the final output).

The **In script text** column is a plain text match: `yes` means the Part 1 value, as printed, appears in `video_script_and_shotlist.md`; `-` means a short count or integer that is not matched by this check.
